# Частота слів у великому текстовому корпусі (топ-100)

Лабораторна робота № 5, варіант 5. Дисципліна «Технології хмарних та розподілених систем й паралельних обчислень».

Програма рахує, скільки разів трапляється кожне слово в одному або кількох текстових файлах UTF-8 (до 1 ГБ), і записує у файл топ-N слів. Є послідовна версія (еталон) і паралельна map-reduce версія на `ExecutorService`. Результати двох версій порівнюються автоматично.

Мова: Java 17+ (перевірено на Temurin 25). Зовнішніх бібліотек немає. Графіки будує Python-скрипт із matplotlib.

## Структура

| Файл | Призначення |
|---|---|
| `src/wordfreq/Main.java` | аргументи командного рядка або діалог у консолі, режими, вивід результатів |
| `src/wordfreq/Corpus.java` | буферизоване читання файлів блоками, розріз блоку по пробілу |
| `src/wordfreq/WordCounter.java` | виділення слів, послідовна та паралельна версії, злиття, вибір топ-N |
| `src/wordfreq/Generator.java` | генератор тестового корпусу заданого розміру (розподіл Ципфа) |
| `src/wordfreq/RunLog.java` | детальний журнал запуску `run_log.txt`: потоки, блоки, метрики, обидва топи |
| `src/wordfreq/Benchmark.java` | серії експериментів, медіана вимірів, запис CSV |
| `src/wordfreq/SelfCheck.java` | самоперевірка: токенізація, розріз блоків, збіг версій при p = 1, 2, 3, 8, 2·ядра+1 |
| `plot_results.py` | графіки, схеми й таблиця `results/analysis.csv` |
| `data/sample.txt` | приклад вхідного файлу (100 КБ) |
| `results/` | результати експериментів (CSV) і рисунки (PNG) |

## Збірка

PowerShell, з кореня проєкту. Якщо `javac` немає в `PATH`, вкажіть повний шлях до JDK, наприклад `$jdk = 'C:\Users\<user>\.jdks\temurin-25.0.4.1\bin'` і `& "$jdk\javac.exe"`.

```powershell
javac --release 17 -encoding UTF-8 -d out (Get-ChildItem src\wordfreq\*.java).FullName
jar --create --file wordfreq.jar --main-class wordfreq.Main -C out .
```

В IntelliJ IDEA: відкрити папку, позначити `src` як Sources Root, запустити `wordfreq.Main` з VM options `-Xmx8g`.

## Запуск

**Без аргументів** (зручно з IDE) програма питає кожен параметр у консолі. Enter залишає значення за замовчуванням:

```
Режим [за замовчуванням: both]:
Вхідні файли UTF-8 (через кому) [за замовчуванням: data/corpus_100mb.txt]:
Кількість потоків [за замовчуванням: 12]:
...
Перезаписати попередні результати: так/ні або yes/no (ні - нова папка run_<дата_час>) [за замовчуванням: так]:
```

Якщо файла `data/corpus_<N>mb.txt` немає, програма генерує його сама (seed 42), тому перший запуск за замовчуванням створює корпус 100 МБ. Файли з іншими назвами мають існувати.

**Що виводиться в режимі `both`:**

- обсяг файлу, кількість і розмір блоків, час читання (окремо від обчислень);
- прогрів JVM: по одному проходу кожної версії перед виміром, щоб JIT-компіляція не спотворювала час;
- `T_seq` і `T_par` зі складовими: підрахунок, злиття, вибір топу;
- для кожного потоку: назва потоку пулу, час роботи, кількість блоків, обсяг, кількість слів і унікальних слів у локальній мапі; `T_max`, `T_avg`, дисбаланс;
- формули з підставленими числами: `S = T_seq / T_par`, `E = S / p`, метрика Карпа-Флатта;
- топ-10 обох версій поруч і перевірка коректності: кількість слів, унікальних слів, слів з різною частотою (повне порівняння мап), збіг топ-100.

Файли результату: `results/top100_seq.txt`, `results/top100_par.txt` і детальний журнал `results/run_log.txt`. Журнал містить параметри та систему, розміри блоків, таблицю потоків (старт і кінець у мс від початку підрахунку), злиття локальних мап, метрики, обидва топ-100 і журнал кожного блоку: який потік його взяв, коли почав і закінчив. У режимах `seq` і `par` пишуться `results/top100.txt` і той самий журнал.

Якщо файл малий, розмір блоку автоматично зменшується (не менше 4 КБ), щоб блоків вистачило на всі потоки.

**З аргументами** (пари `--параметр значення`):

```powershell
# генератор тестових даних: 100 МБ
java -jar wordfreq.jar --generate 100 --output data/corpus_100mb.txt
# послідовна + паралельна версії з порівнянням
java -Xmx4g -jar wordfreq.jar --input data/corpus_100mb.txt --output results/top100.txt --threads 8 --mode both
# лише паралельна, статичний розподіл
java -Xmx4g -jar wordfreq.jar --input a.txt,b.txt --mode par --threads 4 --schedule static
# серія експериментів (файли 10 МБ, 100 МБ, 1 ГБ генеруються, якщо їх немає)
java -Xmx8g -jar wordfreq.jar --mode bench
# повторний запуск, який не чіпає збережені результати
java -Xmx8g -jar wordfreq.jar --overwrite no
# самоперевірка
java -jar wordfreq.jar --mode check
```

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `--mode` | `both` | `both`, `seq`, `par`, `generate`, `bench`, `check` |
| `--input` | `data/corpus_100mb.txt` | один або кілька файлів через кому (для `check` - `data/sample.txt`) |
| `--output` | `results/top100.txt` | файл результату (для `generate` - файл корпусу) |
| `--threads` | кількість логічних ядер | для `bench` - список через кому, за замовчуванням `1,2,4,8,12,16,24` |
| `--schedule` | `dynamic` | `dynamic` - черга блоків; `static` - кожен потік отримує рівний неперервний діапазон блоків |
| `--top` | `100` | скільки слів записати у файл |
| `--block-kb` | `256` | розмір блоку читання, КБ (для малих файлів зменшується автоматично) |
| `--generate`, `--size-mb` | `100` | розмір згенерованого файлу, МБ |
| `--seed` | `42` | зерно генератора |
| `--runs`, `--warmup` | `5`, `2` | кількість вимірів (береться медіана) і прогрівних запусків для `bench` |
| `--csv` | `results/benchmark.csv` | CSV експериментів; поруч пишеться `*_threads.csv` з часом кожного потоку |
| `--overwrite` | `так` | `так`/`yes` - перезаписати результати в `results/`; `ні`/`no` - записати в нову папку `results/run_<дата_час>/`, попередні не змінюються. У командному рядку Windows пишіть `yes`/`no`: кирилиця в аргументах передається до Java як `??` |

**Пам'ять.** Корпус тримається в пам'яті у вигляді блоків `byte[]`, тому купа JVM має бути більшою за обсяг файлу: для 1 ГБ - `-Xmx4g`, для серії експериментів - `-Xmx8g`.

**Кирилиця в консолі Windows.** Якщо замість літер видно `?`, запускайте з UTF-8: `chcp 65001` і `java '-Dstdout.encoding=UTF-8' '-Dstderr.encoding=UTF-8' -jar wordfreq.jar ...` (у PowerShell параметр `-D` береться в лапки). В IntelliJ IDEA це не потрібно.

## Формат даних

**Вхід:** звичайний текст UTF-8, довільні рядки. Словом вважається неперервна послідовність літер Unicode. Апостроф між двома літерами (`'`, `’`, `ʼ`) входить у слово й зберігається як `'` («п'ять», «don't»). Регістр не враховується. Цифри та розділові знаки розділяють слова.

**Вихід:** текстовий файл UTF-8, розділювач - табуляція:

```
# Файли: [data\corpus_100mb.txt]; слів: 12433701; унікальних: 50000
# місце	слово	кількість
1	я	1091724
2	ю	545095
```

Якщо кількість однакова, слова впорядковано за алфавітом, тому результат завжди однаковий.

**Генератор** створює псевдослова з українських складів (словник 50 000 слів). Частоту задає закон Ципфа, як у природній мові: слово рангу k трапляється приблизно в 1/k разів рідше за перше. Речення починаються з великої літери, містять коми й крапки.
